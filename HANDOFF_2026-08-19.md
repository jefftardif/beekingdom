## Architecture patterns (know these before touching code)

- **Runtime bootstraps**: every HiveMap runtime feature is a small `MonoBehaviour` auto-created via `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]`, gated on `scene.name.StartsWith("Environment2D5D")`. No scene wiring. Files: `Assets/BeeKingdom/Playground/HiveMap*Bootstrap.cs`.
- **The monolith**: `Assets/BeeKingdom/Playground/HiveViewProductUiPresenter.cs` (~44k lines, IMGUI) is where almost all drawing/logic lives. Bootstraps call into it via small `...ForExternalHost`-suffixed public static wrapper methods.
- **"Official" vs "local-preview" branching**: every gameplay system has two paths — a real server-backed one (`Official...Configured()` check) and a client-only fake one used before a system existed or when not logged into an official session. The single most common bug this whole project has produced: a real server system gets built and its official helper functions exist, but the actual HiveMap-reachable window never calls them (they were only wired into an old dead `referenceHotspotSelected`-gated panel). **When a feature "looks built but doesn't work on HiveMap," check this first** — grep for where the window/click-handler actually is, and whether it calls the `Official*` functions or only the local-preview ones.
- **Server twin services**: `BuildingUpgradeService` and `CombatRecruitmentService` (`Server/src/BeeKingdom.HiveOperations/`) are structural twins — config/hardcoded catalog, atomic resource debit via `IHiveStateRepository.ExecuteAtomicallyAsync`, real wall-clock timers, idempotency receipts, optimistic concurrency, one-active-operation-per-hive-per-kind. Use these as the template for any new server-authoritative system.
- **Capacity-formula pattern**: `ComputeCapacity(buildingLevels)` — computed on read, never persisted. `CombatSquadReservationService.ComputeCapacity` and the new `CombatRecruitmentService.ComputePopulationCapacity` both follow `InitialX + level*PerLevelBonus`, capped at `MaxX`.
- **Config-array-merge gotcha**: `Microsoft.Extensions.Configuration` merges array-shaped sections (e.g. a JSON `Catalog` array) by index across providers — a smaller test-override provider can't truncate a larger base array. Hit twice this project. Fix: rebuild config from a filtered copy stripping the relevant key prefix before layering overrides.
- **Zero-delay client feedback pattern**: for "is this timer done" UI, compute locally (`EndsAtUtc - (ServerTimeUtc + delta)` checked every frame) instead of waiting on the next poll — frame-perfect, no network dependency — while the actual mutating action (`Claim()`) stays server-gated so the server remains sole write authority. See `IsTrainingReadyToClaimNow` in the Presenter.
- **PowerShell, not Bash**: Jeff is on native Windows PowerShell. Any command given to him must be PowerShell syntax (`$env:VAR = "value"`, `Invoke-RestMethod`), never Bash-style env-prefix or `curl -H`.
